# AGENTS.md

## Commands

- `npm run dev` — dev server on port 5151 (site + Worker-served `/api` proxy; needs `.dev.vars`)
- `cloudflared tunnel --url http://localhost:5151 --http-host-header localhost:5151` — expose the dev server via a quick tunnel; always pass `--http-host-header`, since `server.allowedHosts` is not configured and Vite blocks non-localhost Host headers
- `npm run build` — production build to `dist/`
- `npm run preview` — run the build in the local Workers runtime
- `npm run format` — format `index.html`, `main.js`, and `styles.css` with oxfmt
- `npx wrangler deploy` — manual deploy of site + API proxy as one Worker (run `npm run build` first). Production normally deploys via Cloudflare dashboard Git integration on push to `main`
- `node scripts/generate-icons.mjs` — regenerate `public/` icons from `design/icon.svg`
- `node scripts/build-rail-data.mjs` — rebuild `rail.json` (bundled MRT/LRT data) from `data/sg-rail.geojson` (cheeaun/sgraildata)
- `node scripts/build-rain-data.mjs` — rebuild `rain-pixels.json` (pre-computed 70 km radar pixel→planning-area map) and `areas-idx.json` (slim `[[name, region], ...]`) directly from `data/sg-planning-area.geojson`. Run this single command after changing the source dataset or fixed radar-grid mapping

No lint, typecheck, or test commands exist.

## Environment

Local dev requires `.dev.vars` (copy from `.dev.vars.example`; gitignored) with:

```
DATA_GOV_SG_API_KEY=<data.gov.sg API key>
WAQI_TOKEN=<aqicn.org token; required for the AQI overlay>
```

Production uses Cloudflare **runtime** secrets of the same names (dashboard Settings → Variables & Secrets, or `npx wrangler secret put`). AQI UI is a **build-time** gate: `aqiUiEnabled()` in `vite.config.js` checks `VITE_AQI_UI`, then `process.env.WAQI_TOKEN`, then `.dev.vars`. Dashboard runtime secrets are not visible during `npm run build` — set `VITE_AQI_UI=1` (or `WAQI_TOKEN`) under Settings → Build → Build variables and secrets. Never commit the keys or put them in client-visible code — the whole point of the proxy.

Never commit `.env`, `.dev.vars`, or the API key. Never deploy without being asked.

## Project Structure

Single-page vanilla web app deployed as one Cloudflare Worker: static assets + a same-origin `/api/*` proxy (`worker/index.js`), wired together by the Cloudflare Vite plugin.

- `index.html` — page markup; references `/styles.css` and `/main.js`. One inline `<script>` in `<head>` applies a stored theme override before paint — keep it inline to avoid a flash.
- `styles.css` — all styles (`:root` CSS custom properties handle theming)
- `main.js` — ES module with all app logic
- `NOWCAST.md` — 70km nowcast deep-dive: pipeline, verification, past bugs, tuning constants, and the improvement TODO list. Read it before touching any `NOWCAST_*` code or nowcast logic in `main.js`
- `worker/index.js` — Worker entry: proxies allowlisted `/api/*` paths to `api-open.data.gov.sg`, injecting the API key server-side; upstream fetches are edge-cached 30s via `cf: { cacheTtl: 30 }`
- `wrangler.jsonc` — Worker config (`sg-weather-radar`); assets with SPA fallback, `run_worker_first: ["/api/*"]`
- `vite.config.js` — `cloudflare()` plugin only. MapLibre's worker is wired via `?worker&url` in `main.js` (per MapLibre v6 docs) so Vite emits it as a self-contained chunk — don't switch back to plain `?url`, which emits the worker verbatim without its `maplibre-gl-shared.mjs` sibling and breaks the map in production builds.
- `.dev.vars.example` — template for the gitignored `.dev.vars` local secret file
- `design/icon.svg` — icon master (64×64 grid); all `public/` favicon/tree icons are generated from it by `scripts/generate-icons.mjs` — never edit `public/` icon files directly
- `rail.json` — bundled MRT/LRT lines + stations, delta-encoded int coords at 1e-5°, generated by `scripts/build-rail-data.mjs` from `data/sg-rail.geojson`; imported into the bundle in `main.js` and rendered as always-on `rail-*` layers (lines ≥ zoom 10, stations ≥ 12, labels 13/14)
- `data/sg-planning-area.geojson` — source for the 55 URA planning areas used by `scripts/build-rain-data.mjs`. Source: URA "Master Plan 2025 Planning Area Boundary (No Sea)" layer `G_MP25_PLNG_AREA_NO_SEA_PL` via data.gov.sg dataset `d_2cc750190544007400b2cfd5d7f53209` (Singapore Open Data Licence; fetched 2026-08-30). The build simplifies and delta-encodes geometry in memory; holes (small water bodies) are skipped — they're still counted as part of the area. The new per-polygon containment is the actual URA partition and needs no distance approximation. Known source caveats inherited from the dataset: the layer covers internal waters — the SG side of the Johor Strait up to near the JB coast (worst ~2.8 km of water off Woodlands/Sembawang at lng 103.70–103.87), Keppel Harbour and the Jurong~mainland strait — and Jurong Island, Sudong, Pawai, Hantu are tagged as WESTERN ISLANDS / NORTH-EASTERN ISLANDS planning areas (included). Open southern sea and JB land are excluded
- Dependencies at runtime: `maplibre-gl` + `@scritto/core` (rolling timeline numbers); Vite is the bundler
- `.oxfmtrc.json` — oxfmt config; single quotes for JS

## Architecture Notes

- The app calls same-origin `/api/*` paths only (`apiURL()` in `main.js`); the data.gov.sg API key exists solely in the Worker (`env.DATA_GOV_SG_API_KEY`, sent as the `x-api-key` header). Watch URL construction in the Worker: `new URL(absolutePath, base)` silently drops the base's path — concatenate `API_BASE + path` instead.
- Radar frames from three ranges (70/240/480 km) are rendered inside the map as `image` sources + `raster` layers (`radar-70` on top of `radar-240` on top of `radar-480`, all below boundary layers). Frames are copied into 480×480 canvases (`buildRadarCanvas` in `main.js`) without client-side reprojection; MapLibre projects the image source from its geographic corner coordinates. With clipping on, outer-image columns are cleared only when their full width falls inside the inner range's longitude bounds, while rows whose centers fall inside its latitude bounds are cleared. This avoids a visible side gap while keeping the top and bottom edges aligned. `resampling: 'nearest'` keeps pixel edges hard. Composed canvases are memoized in `frameImageCache` (LRU, 24) keyed by URL + clip state; frame loads are direct CORS fetches from the data.gov.sg CDN.
- All timestamps across ranges are intersected into `allTimestamps`; the time slider indexes into this.
- Rain summary (`analyzeRadar` → `summarizeRain`, 70km range only): every rainy pixel in the pre-computed `rain-pixels.json` map is read directly; the map is a flat delta-encoded `[pixelDelta, areaIdx]` array built once by `scripts/build-rain-data.mjs` from the 55 URA planning area polygons, so the per-frame path has no lat/lng conversion, boundary check, or distance scan — just a pixel→area lookup. The stable pixel→area lookup and flood-fill buffers are allocated once at startup. Only 4-connected rain components within one planning area and with ≥ `MIN_COMPONENT_PIXELS` pixels are reported, ignoring orphan and diagonal-only pixels. The level word is the heaviest level still covering ≥⅓ of reported rain pixels (`dominantLevel`) so a heavy core isn't averaged down by its light fringe. Summaries group repeated areas into concise region labels, append "region" once to region-only lists, use concise mixed region/area wording when useful, and say "across Singapore" when rain spans more than three regions or half the areas. Every summary ends with a period.
- Refresh is slot-aligned: feeds publish on 5-minute slots (`SLOT_MS`); the app polls every 30s only while ranges of the current slot are missing, then idles until the next slot boundary; hidden tabs pause polling.
- A refresh that comes back empty or rejected for one range must not erase that range's existing frames (`applyRadarData`/`mergeRangeResults` keep last-known data) — the 70km feed publishes early (never polled, so its sessionStorage cache ages out and pass 1 can miss it), and wiping on a transient gap blanked its whole tick row until the next poll.
- API responses are cached in `sessionStorage` with prefix `sgwr-api:` and a 60s TTL; first render uses cache synchronously, then a network refresh replaces it if newer data exists. The Worker stays a passthrough proxy; its upstream fetch sets `cf: { cacheTtl: 30 }` so Cloudflare's edge cache absorbs repeat traffic (feeds update at most once a minute → HITs are ≤30s stale). Local dev always shows `cf-cache-status: DYNAMIC` — workerd doesn't simulate the CDN cache; the caching is production-only behavior.
- Abuse protection is the 30s edge cache alone — intentional, no rate limiter (a per-IP `ratelimits` binding was tried and removed for minimalism; don't re-add one unless abuse actually shows up). Repeat requests for a URL never reach upstream; floods of *distinct* URLs (arbitrary date/query params, each a cache miss) would. data.gov.sg's own 429s are the backstop (v2 realtime: 6/12/30 calls per 10s by key tier), which the app rides out on its sessionStorage cache.
- Map: OpenFreeMap styles; style URL swaps on theme change via `map.setStyle()`. Overlay stack is rebuilt on `style.load` in this order: radar rasters → `land-outline` (coastline `line` layer from the style's `openmaptiles` source, `water`/`class=ocean`, so rain stays readable against land) → `land-outline-inland` (same source, `lake`/`pond`/`river`/`canal` classes, `minzoom: 12` so inland water edges only join when zoomed in) → `wind-layer` → boundary outline/label layers → lightning → flood circles/icons. Base-style place-label symbol layers (`source-layer: 'place'`; IDs differ per style, e.g. `place_*` vs `label_*`) are `moveLayer`ed to the top so country/state/region names stay readable above everything.
- Wind particles: NEA station wind speed + direction (data.gov.sg real-time APIs) are merged into u/v vectors and interpolated onto a masked IDW grid (field fades to zero away from stations). Particles animate on an offscreen 2D canvas (persistent trails via `destination-in` fades, batched color-bucket strokes) that a `wind-layer` custom layer uploads as a texture and composites fullscreen — it's a real map layer stacked above the radar rasters and the `land-outline` coastline, and below boundary/lightning layers, so rearrange it like any other; `prefers-reduced-motion` gets a one-shot static streamline render instead. Alongside the trails, stationary DOM `maplibregl.Marker` labels sit on each NEA station (real island coverage) as outline-only one-liners (`5km/h`, no plate), rotated to the local travel direction (eased on field refresh; flipped 180° when that would make the text upside-down) — they do not drift with the field. Shimmer is an animated CSS `mask-image` band on the label itself that goes see-through so the map shows in the sweep (not a second painted color; do not use `background-clip: text` — it never paints under MapLibre’s marker transform). Pace tracks speed (`30/kmh` seconds, 1.5–8s; 10 km/h → 3s). Flipped labels get `animation-direction: reverse`. `prefers-reduced-motion` drops the shimmer and snaps rotation.
- Nowcast inputs: when `sgwr-nowcast` is enabled, wind speed/direction are fetched for model input even if the wind map overlay remains hidden. The display toggle only controls rendering; nowcast uses the retained wind data independently.
- Theme is CSS-first: `:root` holds light values, a `@media (prefers-color-scheme: dark)` query handles the system default, and `:root[data-theme="dark"]` forces dark. A `<meta name="color-scheme">` and the `color-scheme` property keep native UI in sync. JS only sets/removes the `data-theme` attribute for explicit `localStorage['sgwr-theme']` overrides (`system` | `light` | `dark`) and swaps the map style via `map.setStyle()`; an inline head script applies a stored override before paint to avoid flash.
- Settings: opacity (`sgwr-radar-opacity`), boundary clipping (`sgwr-radar-clip`), lightning overlay (`sgwr-lightning`), flood alerts (`sgwr-floods`, default off), wind particles (`sgwr-wind`, default off), temperature (`sgwr-temp`, default off), AQI (`sgwr-aqi`, default off) — all persisted in `localStorage`.
- Temperature overlay: opt-in `sgwr-temp`. Data from `/air-temperature` + `/relative-humidity` (NEA station network) and `/weather?api=wbgt` (NEA WBGT heat-stress network; already allowed via the Worker `/weather` prefix). Wind is loaded for feels-like even when the wind overlay is hidden (same pattern as nowcast). DOM markers are white type with a dark chromatic outline ring (no plate): two-line chips at air-temp stations (`31.7°` + translucent feels-like delta `+2.8°`; integer bold, decimal + degree medium) and one-line WBGT chips only where they fill gaps away from the T network. Numbers use one decimal with trailing `.0` dropped. Feels-like = damped Steadman/BOM AT (10 m wind, light-air floor 1.5 m/s) blended with NWS heat index, then half the raw excess over T (raw HI/AT overshoot in SG humidity; 32°C/78% was +11°). Nearest WBGT within ~3 km floors the feel (sun/wind/humidity); heat stress Low/Moderate/High is tooltip-only, Moderate+ bolds the temp. Outline scale: two OKLCH stops only — cool blue `oklch(0.58 0.16 220)` → warm red `oklch(0.54 0.26 25)`, free-run L/C/H on the short hue arc (via purple, not green). Clamped outside 25–32. A smooth horizontal `temp-gradient` legend (title "Temperature"; 25° / 32°+; `linear-gradient(in oklch …)` so the bar matches the chip hue arc) sits under the precip scale while the overlay is on. Feels-like `+x°` is zoom-gated (`TEMP_FEELS_ZOOM` = 10, the default SG fit) — hidden when zoomed out, shown on hover or zoom ≥ 10. RH is IDW-filled when a station lacks a sensor. Display-only (not timeline-scrubbed).
- AQI overlay: opt-in `sgwr-aqi` toggle (right-side AQI button). Worker `/api/aqi-stations` calls the WAQI map-bounds JSON API (secret `WAQI_TOKEN`, required — `demo` is rejected) for the 480 km radar square only (`n,w,s,e` corner order returns more stations than `s,w,n,e`); the Worker and the client both drop anything outside that box. The map draws DOM `maplibregl.Marker` chips (not WAQI tile images): rounded rect + AQI number using the WAQI map palette (`#009966` only below 50 — 50 paints yellow like their tiles, then `#ffde33/#ff9933/#cc0033/#660099/#7e0023`), background at 88% opacity. Marker z-index interleaves with temp chips (`aqiZIndex`/`tempZIndex`): good AQI &lt; temp&lt;29° &lt; moderate AQI &lt; temp≥29° &lt; unhealthy+ AQI; hover promotes to 501. `#map` is `isolation: isolate` and control corners are forced to `z-index: 1000 !important` so chips stay under map chrome (`maplibre-gl.css` loads after `styles.css` and would otherwise win with `z-index: 2`). Relative age (“22m ago”) sits under the chip on hover or at zoom ≥ 11; text is near-white/near-black mixed with the band hue plus a 1px theme halo (light: black outline + lighter color; dark: white outline + darker). WAQI attribution is added to the attribution control only while the overlay is on. A compact AQI legend (two-column swatch grid, filled top-to-bottom per column: Good/Moderate/Sensitive · Unhealthy/Very Unhealthy/Hazardous) sits under the precipitation scale in the masthead and is shown only while the overlay is on. Edge cache 5 min.
- Flood alerts (PUB `/weather/flood-alerts`): opt-in `sgwr-floods` toggle. Only `msgType: Alert` readings draw (Cancel ends the matching Alert via `references` and is never drawn). Each event draws a `circlePolygon` broadcast radius (km from `area.circle`) as 20% white fill + black dotted outline, plus a white wave icon with black outline at the center. Icon size follows `severity` (Minor 0.85 → Extreme 1.35); `area.areaDesc` labels cycle around the icon (below/above/right/left) with collision drop (`text-allow-overlap: false`, icons stay) and a slightly trimmed label text. Timeline scrubbing shows events active at the selected slot. Cancel closes the event early; if none arrives, it auto-closes 1 hour after Alert (`FLOOD_AUTO_END_MS`). Empty `readings` heartbeats are ignored. The Worker already allows the path via the `/weather` prefix.
- 70km nowcast: opt-in `sgwr-nowcast` enables a client-side CPU ensemble from the latest five 70km frames. It links cells into lineages across all frame pairs, drives displacement from the per-lineage median delta, and per-cell clamped mass-growth rate (multiplied into the fade, plus a level shift), combining centroid, wind, and dense block-matching members. Cells are detected over the whole 70 km frame (sea and Johor included) so the forecast canvas covers approaching weather outside Singapore, while summaries and area votes stay Singapore-only (`rain-pixels.json` lookups). It inserts stable `nowcast:<slot>:<seed>` sentinels for +5/+10/+15 minute timeline slots; the **map** renders the `lookbackNoDecay` field (see below), and ticks/summaries use the same levels. Nowcast frames bypass `frameImageCache` (same-seed recompute used to re-serve stale bitmaps). Validation uses a neighborhood-pooled Jaccard (max-pool radius `NOWCAST_FIT_POOL`, 4 px ≈ 1.2 km) against actuals, always alongside a no-motion persistence baseline; the rolling fit keeps one sample per live slot. When a forecast slot becomes live, every member (`median`, `wind`, `dense`, `display`, `lookback`, `lookbackNoDecay`) plus `persistence` at each lead (+5/+10/+15) is scored, logged, and persisted to localStorage `sgwr-nowcast-scores`; `nowcastScores()` in the console summarizes it. Pending forecasts and fit samples persist across reloads (`sgwr-nowcast-pending`, `sgwr-nowcast-fit`). The **map renders the semi-Lagrangian `lookbackNoDecay` member** (`lookback` = same plus level decay, scored only) (one smooth motion field, backward sampling, no fill passes); the old forward-splat `display` is still computed only so it keeps being scored. Input frames must be consecutive 5-min slots (stops at the first gap). Cells touching the frame edge are excluded from motion/growth estimates; dense flow treats textureless blocks as unknown and fills them from neighbours; the scored-only `lookback` member's decay lowers levels (never raises) and drops tiny cells at longer leads — kept off the map because it made light rain vanish. Score records carry a version (`NOWCAST_SCORE_VERSION`) — bump it when forecast logic changes. The feature is gated off for stale or unaligned feeds and never changes the Worker/API. Full detail in `NOWCAST.md`.
- All times displayed in `Asia/Singapore`.

## Conventions

- Comments sparingly: 1 line, 2 max for genuinely complex constraints. No wordy multi-line explanations.
